# 에이전트 집 기반 결과공간 방향

## 구현 상태

P0 v1 구현 완료. 집 클릭/문 앞 진입 시 열리는 기존 패널에 `서비스`와
`최근 결과` 탭이 생겼다. 정적 배포에서는 `agent-results.json`을 읽고,
라이브 상태의 `result` 또는 `results[]`가 있으면 그 값을 우선 표시한다.

## 결정

Mini Planet의 결과 전시는 별도 기록관을 새로 짓지 않고 **각 에이전트의 집을
그 에이전트의 개인 결과공간으로 확장**한다. 집 문은 지금처럼 서비스 패널로
연결되고, 같은 패널 안에서 `서비스`와 `최근 결과`를 나누어 보여준다.

중앙 기록관은 보존 기간, 검색, 공개 범위가 필요한 시점까지 보류한다. 현재는
새 랜드마크를 더하는 것보다 여섯 집의 의미를 선명하게 만드는 편이 행성의
시각적 위계와 에이전트 소유감을 모두 지킨다.

## UI 원칙

- 기존 집 클릭/문 앞 인터랙션은 유지하고 패널 내부만 확장한다.
- 기본 탭은 `서비스`, 두 번째 탭은 `최근 결과`로 둔다.
- 최근 결과는 최대 6개만 노출하고 제목, 한 줄 요약, 종류, 갱신 시각, 안전한
  링크만 표시한다.
- 결과가 없으면 장식용 빈 진열대 대신 조용한 빈 상태를 보여준다.
- 집 외형에는 작은 작업 흔적 한두 개만 더하고, 상태 애니메이션과 경쟁하는
  상시 이펙트는 두지 않는다.

## 데이터 경계

결과 목록은 배포 후 Mac mini의 읽기 전용 Hermes 브리지가 제공하는 정제된
`result` 또는 공개 artifact projection을 사용한다. 전체 SOUL, 프롬프트,
터미널 로그, 로컬 절대 경로, 비공개 저장소 URL은 브라우저로 보내지 않는다.
`config/agents.json`의 `resultSpace`는 공간 이름과 설명만 담으며 결과 데이터의
원천이 아니다.

## 공개 결과 계약 v1

`agent-results.json`은 `agents.<agent-key>[]` 형태이며 각 결과는 아래 선택형
필드만 사용한다. 배열은 최신순으로 최대 6개다.

```json
{
  "id": "stable-public-id",
  "kind": "briefing | decision | operations | build | verification | content | research | report | commit | image | link | artifact",
  "status": "ready | review | draft | live",
  "title": "공개 제목",
  "summary": "180자 이하 공개 요약",
  "updatedAt": "ISO-8601",
  "url": "선택형 http(s) 공개 링크"
}
```

- 현재 작업 결과인 `agent-status.json`의 `result`가 가장 먼저 표시된다.
- 같은 상태 항목의 `results[]`가 있으면 그다음에 최신순으로 합친다.
- 정적 `agent-results.json`은 라이브 결과가 부족할 때만 남은 칸을 채운다.
- 중복 `id`는 한 번만 표시하며 알려지지 않은 종류·상태는 안전한 기본값으로
  정규화한다.
- 인증 정보가 든 URL과 공개 사이트에서의 localhost·사설망 URL은 링크로
  만들지 않는다.
