# v112 마을 비율과 실제 보행 화면 개선

## 작업 범위

장미가 크고 배치가 마을처럼 보이지 않는다는 의견에 따라 v111의 장미 축소와 앞쪽 가로 재배치에 이어, 사람·문·길의 비율과 실제 탐험 시점을 수정했습니다. 엔진 변경, 행성 확대·축소, 새 집 추가, 원격 배포는 하지 않았습니다.

## 원인과 조치

| 확인한 문제 | 반영한 변경 |
| --- | --- |
| 일부 에이전트 키보다 집 문이 낮음 | 캐릭터 공통 배율 0.84 → 0.72, 일반 주택 문 높이 1.78 → 2.15, 등대 문 높이 1.18 → 1.70. 문틀의 실제 구멍도 함께 수정 |
| 잔디, 앞마당, 광장의 용도가 색만으로 분명하지 않음 | 광장과 주도로에 넓은 종이 돌 포장 추가. 주택 앞마당에도 작은 포장면 적용. 초록 골목은 유지 |
| 광장 중심물이 마을 시설보다 추상적인 상태 표시처럼 보임 | 기존 6명 상태 표시를 낮은 분수 형태로 변경. 상태 연결과 상호작용 계약은 유지 |
| 실제 탐험 화면에 하늘이 많고 집이 지평선 뒤로 숨음 | 기본 카메라 거리 4.3 → 6.3, 높이 각도 0.34 → 0.72. 모바일은 7.2 / 0.78. 고정된 머리 높이 대신 몸과 앞길을 보도록 수정 |
| 가려진 북쪽 장미 이름이 마을 앞쪽에 뜸 | 반구 방향 비교에 더해 실제 시선과 행성 구체의 교차를 검사. 건물 뒤 이름 가림도 유지 |
| 집 접근 검사에서 잔디 지름길이 허용됨 | 본토 집 왕복 검사는 실제 도로·골목 그래프만 사용. 움직임 자체는 기존 충돌·수역 판정 함수를 사용 |

포장 돌은 낱개 오브젝트가 아니라 구역별 한 메시로 묶었습니다. 그림자를 만들지 않아 작은 틈에서 발생하는 그림자 떨림을 피하고, 광장 타일 수와 긴 사용자 경로의 세부 장식량을 제한했습니다.

## 현재 크기와 배치 기준

아래 값은 실제 미터가 아니라 장면 좌표 단위입니다.

- 행성 반지름 7.47, 지름 14.94, 둘레 약 46.94. 이번에는 변경하지 않았습니다.
- 표면 표본 4,096개 기준 육지 57.4%, 수역 42.6%. 특정 시점에서 보이는 바다 면적과는 다릅니다.
- 방문자 높이 0.972, 주도로 폭 0.90, 골목 폭 0.70. 도로 폭은 늘리지 않았습니다.
- 주택 문 높이 1.226~1.266, 등대 문 높이 1.462. 방문자 키 대비 1.26~1.50배입니다.
- 각 집 문의 높이는 해당 에이전트 키보다 1.12~1.40배 높습니다.
- 가장 가까운 집 중심 간 구면 거리는 로디–율 3.497입니다. 기존 건물 겹침과 문 앞 여유 검사는 유지했습니다.
- 편집 가능한 소품은 29개입니다. 빈곳을 반복 장식으로 채우지 않았습니다.

행성을 줄이면 곡률과 건물 쏠림이 더 강해지고, 늘리면 집 사이 이동 거리와 빈 공간이 커집니다. 현재 문제에는 행성 크기보다 상대 비율과 카메라 조정이 우선이라고 판단했습니다.

## 공간 구성 판단

1. 앞면은 작은 항구 마을입니다. 분수 광장이 기준점이고 로디의 관제 집, 양옆 자비스·율의 집이 가로를 만듭니다. 남쪽 길은 항구로, 양옆 골목은 뒤편으로 연결됩니다.
2. 뒤편은 앤·루드비히의 조용한 주거지입니다. 정자가 두 집의 공용 목적지이고 연결 골목을 통해 앞마을로 돌아옵니다.
3. 북극의 장미는 생활 시설이 아닌 별도 정원입니다. v111에서 전체 크기를 60%로 줄인 상태를 유지했습니다. 나침반 기준점과 이야기 기능은 유지됩니다.
4. 아르고스 등대와 남쪽 정원은 항해 목적지입니다. 부두, 상륙, 재탑승을 포함한 왕복 연결을 유지했습니다.

전면의 분수·집·항구는 이전보다 마을의 중심과 방향이 분명해졌습니다. 뒤편은 전면보다 여유 있는 정원 주거지로 남겼습니다. 행성 전체를 동일한 밀도의 도시로 만들거나, 실제 크기의 오픈월드로 확장한 것은 아닙니다.

## 검증

- 전체 자동 테스트 196개 통과.
- 배포 전 문법·캐시·에이전트 데이터·GLTF 검사 통과.
- 도로 12개, 중앙·보행 가장자리 2,430개 표본: 충돌 0, 수역 침범 0.
- 본토 5개 집: 제작된 길을 따른 방문·문 도착·왕복 모두 통과.
- 집 6곳: 입구 안내, 서비스 패널, 결과 공간 검사 통과.
- 항구 → 등대 부두 → 등대 문 → 남쪽 정원 → 항구의 16단계 이동 통과. 검사 후 배와 방문자 위치 복원.
- 데스크톱 1280×900 기본 배치, 모바일 390×844 저장 배치에서 통합 검사 통과. 화면 밖 가로 넘침 없음.
- 실제 탐험 기본 카메라로 화면 검증. 장소별 개발용 시점에 있던 별도 카메라 보정은 제거하여 실제 화면과 검사 화면이 같도록 했습니다.
- WebGL 화면 표본에서 데스크톱 40개, 모바일 36개의 서로 다른 색상 확인. 화면이 비어 있지 않으며 캐릭터와 배 애니메이션이 지속됨을 화면으로 확인했습니다.
- 확인한 화면에서 브라우저 오류·경고 없음.

브라우저의 모바일 화면 크기 검사는 실제 저사양 휴대전화 성능 검사가 아닙니다. 마을의 미적 완성도도 자동 검사 점수로 보증하지 않습니다. 현재 결과는 소규모 페이퍼컷 항구 마을에 맞춘 비율·동선·시점 개선이며, 신규 지역이나 인테리어 콘텐츠 확장은 별도 범위입니다.

## 수정 파일

- `src/main.js`: 캐릭터·문·분수, 포장면 연결, 기본 탐험 시점, 이름 가림, 실제 길 왕복 검사.
- `src/world/paper-assets.js`: 높아진 문의 실제 정면 개구부.
- `src/world/village-paving.js`: 구면 지형을 따르는 묶음 포장 메시.
- `src/world/spatial-structure.js`: 도로 그래프 경로 검사, 구체 시선 가림 판정.
- `tests/village-proportions.test.mjs`: 포장면 방향·반경·범위·예산, 가림, 데스크톱·모바일 카메라 비율.
- `tests/home-walks.test.mjs`, `tests/paper-assets.test.mjs`, `tests/world-art-direction.test.mjs`: 관련 회귀 검사.
- `index.html`, `src/boot.js`, `sw.js`: v112 연결 및 캐시 갱신.

이번 v112는 저장된 집 좌표를 추가로 덮어쓰지 않습니다. v111의 기본 가로 변경은 기존의 백업·사용자 수정 보호 규칙을 따릅니다. 임의로 만든 모든 사용자 배치의 통과까지 보증하는 것은 아닙니다.
