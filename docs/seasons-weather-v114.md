# v114 계절 · 날씨 적용 및 검증 기록

작성일: 2026-09-12 KST

## 적용 기준

- 기존 Three.js와 페이퍼컷 에셋을 유지합니다. 엔진 교체나 추가 외부 라이브러리는 없습니다.
- 서울 시각이 태양의 24시간 공전을 결정합니다. 같은 순간 서로 반대인 표면은 낮·밤이 반대입니다.
- 관제에서는 보고 있는 카메라 방향, 탐험에서는 플레이어 위치, 편집에서는 편집 카메라 방향을 사용합니다.
- 시계와 실제 날씨는 앞쪽 서울, 뒤쪽 리우를 기준으로 합니다. 두 도시의 시차는 12시간입니다.
- 리우는 기존 시스템의 반대편 기준 도시입니다. 서울의 정확한 지리적 대척점이라는 의미는 아닙니다.
- 계절은 행성 전체에 서울 달력을 적용합니다. 봄 3~5월, 여름 6~8월, 가을 9~11월, 겨울 12~2월입니다.
- 낮·밤은 게임용 근사 모델입니다. 서울의 실제 일출·일몰, 절기별 일조 시간, 천문학적 태양 고도까지 재현하지는 않습니다.

## 사용자 경험

시계 옆 날씨 아이콘에서 작은 메뉴를 엽니다.

- 날씨: 실제 날씨 / 맑음 / 흐림 / 비 / 눈.
- 계절: 서울의 계절 / 봄 / 여름 / 가을 / 겨울.
- 기본값은 실제 날씨와 서울의 계절입니다. 사용자가 고른 연출 설정은 해당 브라우저에만 저장합니다.
- 연출 날씨에는 실제 온도를 붙이지 않습니다. 실제 정보, 저장된 최근 정보, 연결 대기를 구분합니다.
- 361~440px 화면에서는 상단 온도를 숨겨 제목과 겹치지 않게 하고, 메뉴 안에는 실제 온도를 표시합니다.
- 키보드로 선택 가능하며 Escape, 닫기 버튼, 바깥 클릭으로 메뉴를 닫을 수 있습니다.

## 표현 범위

- 기존 행성 바탕, 섬의 잔디, 정원, 테라스의 잔디 면에 계절색을 적용합니다.
- 종이 나뭇잎의 녹색 면만 변경하고 잘린 종이 가장자리와 잎맥은 보존합니다.
- 상록수는 가을에 갈색으로 바뀌지 않게 처리했습니다.
- 집 지붕, 에이전트 시그니처 색상, 도로, 바다 색은 변경하지 않습니다.
- 눈은 천천히 내려오는 종이 조각 형태, 비는 기존 선 입자를 재사용합니다.
- 구름·강수 효과는 완만하게 전환합니다. 번개 섬광이나 화면 흔들림을 추가하지 않습니다.
- 눈이 온다고 바다가 얼거나 이동 판정이 바뀌지 않습니다. 겨울 지면색은 계절 연출이며 실제 적설 시뮬레이션이 아닙니다.

## 성능 및 실패 대응

| 항목 | 처리 |
| --- | --- |
| 눈 입자 | 고품질 240 / 균형 160 / 저사양 96, 하나의 Points 메시 |
| 비 입자 | 기존 고품질 460 / 균형 380 / 저사양 300 유지 |
| 구름 | 기존 18개 재사용 |
| 계절색 | 계절이 바뀌고 해당 오브젝트가 보일 때만 갱신, 매 프레임 지형 재생성 없음 |
| 날씨 계산 | 최대 초당 5회, 화면 값은 변경될 때만 작성 |
| 실제 날씨 | 화면이 활성 상태일 때 10분 간격, 서울·리우 각 1회, 중복 요청 합치기 |
| 연결 실패 | 요청 및 응답 본문 6초 제한, 최근 정보 최대 3시간 유지 |
| 오프라인 시계 | API와 무관하게 현재 시각과 고정 도시 시차로 계산 |
| 모션 줄이기 | OS 설정에 따라 눈·비 입자 정지, 하늘·계절색은 유지 |
| 보안 | 좌표는 두 기준 도시로 고정, 사용자 위치 권한 불필요, 잘못된 응답·캐시·프리셋 거부 |

렌더링은 방문자의 브라우저가 담당하므로 눈·비 때문에 M1 서버에 3D 연산이 추가되지는 않습니다. 신규 외부 이미지 다운로드도 없습니다. 현재 정적 배포본은 95파일, 약 3.56MiB로 기존 v113 대비 약 0.02MiB 증가했습니다.

## 검증

- 기존 202개와 신규 60개를 합친 262개 테스트 통과. 신규 검증은 모델 21개, 저장소 18개, 표면/입자 3개, 실제 하늘 모듈 통합 18개입니다.
- KST 월 경계, 모든 계절, 서울/리우 시차, 임의의 반대편 낮·밤, 도시 경계 흔들림 방지 확인.
- 실제 UI에서 맑음·흐림·비·눈과 네 계절을 전환하고 강수 종료 후 남는 입자가 없는지 확인.
- 실제 Open-Meteo 응답 수신 후 자동 날씨·서울 달력 모드로 복귀 확인.
- 1440×900 데스크톱 및 390×844 모바일에서 캔버스 비어 있지 않음과 기존 이동/항구 QA pass 확인.
- 모바일 저사양에서 눈 96개, 수평 넘침 없음, 날씨 HUD와 제목 겹침 없음 확인.
- 360×740 좁은 화면에서도 메뉴가 화면 안에 들어오고 자동 모드 선택이 가능한지 확인.
- 편집 모드 진입 후에도 날씨와 시간 갱신 유지 확인.
- 배포 전 문법·설정·캐시 검증과 정적 배포본 검사 통과.

실제 저가형 휴대폰의 발열·배터리·장시간 FPS는 아직 실기기 검증하지 않았습니다. 자동 품질 조절을 유지하지만 모든 기기에서 고정 60fps나 사용자 평점 4점 이상을 보장하는 의미는 아닙니다.

## 공개 출시 전 남은 판단

[Open-Meteo 요금 안내](https://open-meteo.com/en/pricing)에 따르면 무료 API는 비상업용입니다. 상업 서비스에는 상업 이용 플랜 또는 적절한 다른 공급 방식이 필요합니다. 현재 구현에 유료 API 키를 넣거나 구독을 신청하지는 않았습니다.

상업 출시 단계에서는 방문자마다 외부 API를 호출하는 현재 방식 대신, M1 서버가 두 도시의 날씨를 10분마다 한 번씩 가져와 공용 JSON으로 제공하는 방식을 권장합니다. API 키는 서버에만 보관해야 합니다. 이는 동시 사용자 수에 비례하는 API 호출과 클라이언트 키 노출을 막는 별도 배포 작업입니다. 브라우저당 현재 요청은 최대 시간당 약 12회이며, 방문자 증가에 따라 합산 호출량이 늘어납니다.

이번 변경은 로컬 구현 및 검증까지입니다. 기존 미커밋 v113 서비스 목록 변경을 보존했으며, 커밋·GitHub 배포는 하지 않았습니다.
