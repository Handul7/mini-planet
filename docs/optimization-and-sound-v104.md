# v104 최적화와 소규모 효과음

작성일: 2026-09-11 KST

## 범위

v103의 행성 구조와 페이퍼컷 디자인을 유지한 경량화 작업이다. 집·길·배 위치와 크기, 지형 비율, 저장 키 v27은 변경하지 않았다. 에셋 수를 늘리거나 엔진·프레임워크·외부 의존성을 추가하지 않았다. 사운드와 에셋 경량화는 두 하위 에이전트에 분리하고, 메인 작업에서 통합·회귀 검증했다.

## 효과음

기존 환경음과 동일한 AudioContext와 소리 버튼을 사용한다. 음원 파일 다운로드는 없다.

- 승선: 짧은 상승음, 약 0.18초.
- 하선 성공: 낮게 내려오는 음, 약 0.16초.
- 에이전트 카드·집 서비스·마을 게시판 열기: 작은 상승음, 약 0.12초.
- 변경된 배치의 저장 성공: 짧은 확인음, 약 0.20초.
- 기존 에이전트 작업 완료 알림은 유지한다.

기본은 음소거다. 오른쪽 위 소리 버튼으로 환경음과 효과음을 함께 켜고 끈다. 효과별 0.25~0.35초 재생 제한, 완료 알림을 포함한 발진기 최대 4개 제한, 재생 종료 시 노드 연결 해제를 적용했다. 음소거·숨김 시 소리를 차단하고 오디오 처리를 중지한다. 빠른 토글, 지연된 resume, 실패한 suspend 등이 최신 사용자 선택을 덮어쓰지 않도록 처리했다.

## 확인한 효과

- 안정적인 라벨 60프레임 테스트: 크기 측정 1회, 캐시 재사용 59회.
- 브라우저 관측: 크기 측정 144회, 캐시 사용 7,848회. 해당 구간 요청의 약 98.2%를 재사용했다. 전체 CPU가 98% 감소했다는 뜻은 아니다.
- 6겹 stone 윤곽 삼각분할 6→1회, 5겹 hull 5→1회, 3겹 blossom과 중심부는 4→2회.
- 90가지 레이어 조합에서 최적화 전후 정점·법선·색상·UV 및 경계가 일치했다.
- 에셋 출력 메시 수, 삼각형 수, GPU 버퍼 크기는 줄이지 않았다. 이번 에셋 변경은 생성 연산과 임시 압출 작업을 줄이는 것이다.
- 현재 브라우저에서 60fps 관측 구간이 있었지만, 장면·품질·창 크기에 따라 값이 달랐다. 동일 조건의 장시간 FPS 향상률이나 실제 모바일 기기 성능을 보장하지 않는다.

## 검증 결과

- `node --test tests/*.test.mjs`: 157개 통과. 기존 117개와 신규 40개.
- 신규 검사: 렌더 루프·라벨 캐시·수역 비교 6개, 에셋 동일성·자원 해제 3개, 오디오 생명주기·효과음·실패 및 경쟁 상태 31개.
- 기본 배치 런타임 QA 통과. 6개 집, 2개 공용 공간 연결 및 항구 왕복 8단계 통과.
- 도로 9개, 표본 1,599개에서 장애물·수면 침범 0.
- 캔버스 픽셀 검사로 비어 있지 않은 렌더링 확인. 모바일 390×844 화면과 데스크톱 레이아웃 1280×800 확인, 가로 넘침 없음.
- 게시판·에이전트 카드 열기, 소리 켜기 후 효과음 예약, 재생 종료 시 활성 음성 0, 음소거 후 suspended 상태 확인.
- 개발자 콘솔 경고·오류 없음.
- 숨김·복귀와 오디오 실패 경쟁 상태는 제어 가능한 모의 환경 테스트로 검증했다. 실제 iPhone/Safari의 자동재생 정책 및 스피커 청감은 별도 실기기 확인이 필요하다.
- 배포 전 검증 및 정적 빌드 수행. 공개 산출물 85개, 약 3.48 MiB. 커밋과 원격 배포는 수행하지 않았다.

## 남은 사항

저장 배치의 오브젝트 27개와 도로 검사는 유지됐다. 다만 v103에서 확인한 사용자 배의 부두 접근 문제는 남아 있다. 배가 승선 부두에서 6.282 월드 단위 떨어져 있어 저장 배치의 왕복 QA는 `boat-outside-pier-reach`로 실패한다. 이번에는 배를 임의로 이동하지 않았다. 기본 배치의 왕복 성공과 저장 배치의 실패를 구분해야 한다.

Mac mini M1에서 정적 파일을 제공하는 구조는 그대로다. 3D와 오디오 연산은 접속한 브라우저에서 수행하므로, 이번 변경의 주된 이득은 클라이언트의 반복 작업과 숨겨진 탭의 소비 감소다. Hermes 연결과 서버 운영 검증은 이번 범위에 포함하지 않는다.
