## 서로 다른 두 자동화

**업무 자료:** 로그인한 페이지가 보이면 15초마다 맥미니를 조회한다. 작업실 패널을 닫아도 계속한다. 브라우저 탭을 숨기면 조회를 멈추고 개인 표시를 지우며, 복귀 시 세션과 자료를 다시 확인한다. 로그아웃하면 기록을 비운다. 보드의 진행 수는 주민 전체의 온라인/활동 상태가 아니다.

**화면 코드:** 코드 저장만으로 운영 화면을 바꾸지 않는다. 운영할 변경이 `main`에 반영되고 검사를 통과하면 CI가 UI 릴리즈를 발행한다. 맥미니가 이를 받아 자동 적용한다. 사용자가 ZIP을 반복 전송할 필요가 없어진다.

```text
맥북에어·휴대폰 브라우저
  → https://사용자-도메인/?owner=1
  → Cloudflare Tunnel
  → 맥미니 개인 작업실 (같은 출처의 화면 + 로그인 + API)
  → 기존 컨트롤러 → Hermes

GitHub main → 테스트·공개 파일 검사 → UI 릴리즈
  → 맥미니 갱신기 → 검증·백업·교체 → 정상 확인 / 실패 시 복구
```

도메인은 맥미니의 loopback 서비스를 가리키는 HTTPS Tunnel에 연결한다. 브라우저에 컨트롤러 키를 보내지 않는다. [Cloudflare 공식 설정](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/configuration-file/).

## 준비한 자동 배포 파일

- `.github/workflows/owner-ui-release.yml`: `main` 검증 후 `owner-ui-<커밋 SHA>` prerelease를 발행. 공개 `_site` 파일만 포장한다.
- `scripts/owner-ui-update.py`: 공개 GitHub 저장소의 완성된 UI 릴리즈를 찾고 SHA-256, API 계약 버전, 압축 경로/파일 종류/크기를 검사한다. 내려받은 코드를 맥미니에서 실행하지 않는다.
- 새 UI를 적용할 때 기존 `ownerctl.py stop/start`만 사용한다. backend·비밀번호·Hermes·컨트롤러는 교체하지 않는다.
- 새 HTML·핵심 JS·서비스 워커와 커밋 식별 파일의 실제 응답 해시 및 로그인 전 세션 차단을 확인한다. HTML이 같아도 이전 JS를 계속 제공하면 실패로 판정한다. 실패하면 이전 UI로 되돌리고 같은 실패 릴리즈를 반복 적용하지 않는다.
- 이 첫 버전은 작업실 서버를 짧게 재시작하므로 기존 로그인 세션이 만료된다. 이전 UI 폴더는 자동 삭제하지 않는다.

`main` 검사를 요구하는 저장소 규칙과 릴리즈 쓰기 권한이 신뢰의 기준이다. SHA-256은 다운로드 일치 검증이며 서명을 대신하지 않는다. 비공개 저장소의 인증 다운로드는 이 갱신기에서 지원하지 않는다.

## 맥미니에서 최초 한 번 확인할 사항

1. 이 변경을 검토하여 GitHub `main`에 반영하고 UI 릴리즈가 실제 발행되는지 확인한다.
2. 로디의 사전 점검에서 helper의 해시 잠금 대상은 `owner-server.py`이고 `_site`는 제외되며, stop/start는 owner만 대상으로 함을 확인했다. 설치 직전 동일한 helper인지 재확인한다. helper는 8787 충돌 시 다른 포트를 선택할 수 있으므로 `ownerPort`와 실제 포트가 다르면 설치를 중단하고 원인을 해결한다. 갱신기는 지정한 포트만 검사하며 다른 포트를 추정해 따라가지 않는다.
3. 갱신기를 `_site` 밖의 전용 경로에 설치하고 아래 설정을 실제 경로에 맞춰 권한 `600` 파일로 저장한다. 예시 경로는 기존 보고서 기준이며 설치 시 재확인이 필요하다.

```json
{
  "repo": "Handul7/mini-planet",
  "siteRoot": "/Users/rodiclawmini/.hermes/workspace/projects/mini-planet-owner-20260925/mini-planet-owner/_site",
  "ownerctl": "/Users/rodiclawmini/.config/mini-planet-owner/ownerctl.py",
  "python": "/Users/rodiclawmini/.hermes/hermes-agent/venv/bin/python",
  "stateDir": "/Users/rodiclawmini/.config/mini-planet-owner/ui-update-state",
  "ownerPort": 8787
}
```

4. `python owner-ui-update.py --config <설정파일>`로 다운로드 검증만 실행한다. 처음 적용은 같은 명령에 `--apply`를 붙여 실행하고 로그인·업무·일정·로디 요약·로그아웃을 확인한다.
5. 성공 후 macOS `launchd`에 절대 Python/스크립트/설정 경로와 `--apply`, `StartInterval=300`, 중복 방지 lock을 사용하는 작업을 등록한다. 사용자 로그인 세션 없이 재부팅 후에도 운영할 필요가 있으면 LaunchDaemon + 지정 사용자 구성이 필요하다. 단순 LaunchAgent는 그 사용자 로그인 이후에 실행되므로 상시 서버 요건을 자동 충족하지 않는다.
6. owner 서버와 Tunnel도 기존 운영 방식에 맞게 자동 시작을 구성한다. 갱신기는 기존 owner가 정상인지 먼저 확인하므로 서버 기동을 대신하지 않는다.
7. 도메인 결정 후 Tunnel과 owner의 `--public-origin https://실제호스트`를 함께 설정한다. **로디가 확인한 기존 helper는 이 옵션을 전달하지 않는다.** 현장 helper의 시작 인자와 소스 확인 정책을 함께 점검해 옵션 전달을 보완해야 한다. 갱신기 설정에도 같은 `publicOrigin`을 추가한다. Host/Origin 보존, 개인 호스트 캐시 우회, Secure 쿠키, 로그인 POST와 로그아웃을 실제 HTTPS 주소에서 검증한다.

도메인 연결과 자동 배포는 독립적으로 설치할 수 있다. 도메인 구입을 기다리지 않고 현재 비공개 접속 상태에서 자동 배포를 먼저 시험할 수 있다.

## 복구와 운영 범위

- `stateDir/current.json`: 마지막 성공 커밋과 이전 UI 경로.
- `stateDir/failed.json`: 적용 실패한 커밋. 원인 해결 후 운영자가 이 기록을 치우면 재시도할 수 있다.
- `stateDir/pending.json`: 도중 중단/복구 실패 기록. 이 파일이 있으면 추가 업데이트를 멈춘다. 현재 `_site`, 기록된 백업, owner 프로세스를 확인해 복구한 뒤에만 지운다.
- `.owner-ui-backup-*`: 이전 공개 화면. 정상 운영과 복구 검증 후 오래된 백업을 정리한다.
- UI 적용 검증은 화면 전환과 인증 경계 검사다. 업무 원문을 읽는 로그인 후 전체 검증을 대신하지 않는다.
- `--apply`가 없는 실행은 서버를 중지하지 않는 다운로드 검증이다. `src/owner-release.json`의 커밋이 manifest와 일치해야 한다. 오류 로그는 비밀값 대신 `missing_release_identity`, `existing_owner_healthcheck_failed` 같은 고정 원인 코드를 표시한다.
- 로그아웃 전송이 실패하면 현재 페이지에서 자동 세션 복귀를 막고 재로그인 또는 서버 로그아웃 재시도를 기다린다. 서버 측 로그아웃 성공을 대신하지 않으며, 페이지를 새로 열기 전에 로그아웃을 다시 확인하는 것이 필요하다.
- 새 대화·업무 실행 API를 추가하면 backend 변경은 별도로 배포해야 한다. 이 자동화는 UI 계약 버전 1의 화면 갱신만 담당한다.

## 최초 설치를 맡길 Hermes용 요청문

아래는 매번 전달할 변경 요청이 아니라, 위 준비물이 GitHub에서 사용 가능해진 뒤 **한 번 설치할 때**의 요청이다.

> 미니플래닛은 맥미니에서 화면과 서버를 운영하고, 맥북에어는 도메인 접속만 하도록 구성한다. 저장소의 docs/owner-cloud-roadmap-ko.md와 scripts/owner-ui-update.py, .github/workflows/owner-ui-release.yml을 확인하라. 현재 ownerctl.py의 대상 프로세스·소스 해시 잠금·실제 _site 경로를 먼저 확인하고, 기존 helper와 호환되는 경우 UI 갱신기 검증 → 첫 적용 → 복구 시험 → 5분 간격 자동 실행을 구성하라. Hermes와 컨트롤러를 재설치하거나 재시작하지 말고 비밀번호·API 키·쿠키·업무 원문을 보고서에 출력하지 마라. 도메인이 아직 없으면 도메인 연결만 미설정으로 남기고, 서버 재부팅 후 자동 기동 여부와 자동 UI 업데이트의 실제 커밋을 구분하여 보고하라. 도메인이 정해지면 동일 출처 HTTPS Tunnel과 public-origin을 맞추고 실제 로그인·자동 조회·로그아웃을 확인하라. 경로·포트·권한이 보고서와 다르면 현재 값으로 확인하되, UI 검증 성공을 Hermes 실행/쓰기 연동 성공으로 확대하지 마라.
