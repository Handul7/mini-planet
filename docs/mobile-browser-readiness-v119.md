# v119 모바일 및 PC 브라우저 보완

## 결론

기존 3D 페이퍼컷 캐릭터, 행성 배치, 집과 서비스 연결은 유지했다. 모바일 입력과 반응형 조작부, 저사양 자동 화질 조절을 보완했다. Windows 전용 기능이나 사용자 에이전트 문자열 분기는 추가하지 않았다.

이번 결과는 모든 기기에서 동일한 FPS를 보장하거나 Windows 실기기 검증을 대신하지 않는다. 공개 출시 전 실제 iPhone Safari, Android Chrome, Windows Chrome/Edge/Firefox의 짧은 실기기 검증이 남아 있다.

## 확인한 문제와 조치

| 문제 | 조치 | 파일 |
| --- | --- | --- |
| 전역 포인터 이동이 다른 손가락의 조작과 섞일 가능성 | 캔버스에서 시작한 포인터만 추적하고 한 손가락 회전과 두 손가락 확대를 분리 | `src/input-controls.js`, `src/main.js` |
| 조이스틱이 다른 손가락의 이동/해제 이벤트에 반응 | 최초 포인터 ID 하나만 추적, 실제 스틱 크기로 이동 반경 계산 | 위와 같음 |
| 취소, 캡처 상실, 화면 회전, 탭 이탈 후 남은 입력 | 이동값과 스틱 표시 초기화, 카메라 드래그 종료, 편집 중 미완료 클릭 취소 | 위와 같음 |
| 드래그 후 처음 위치로 돌아오거나 핀치한 뒤 카드가 열릴 가능성 | 제스처 도중 이동량을 확인하고 멀티터치에서 클릭 후보 취소 | `src/main.js` |
| 브라우저마다 휠의 픽셀/줄/페이지 단위가 다름 | 단위를 정규화하고 과도한 한 번의 확대량 제한 | `src/input-controls.js` |
| 320px 화면의 조이스틱과 동작 버튼 겹침 | 스틱 104px, 동작 버튼 48px, 간격 재배치, 감정 버튼 한 줄 정리 | `src/style.css` |
| 가로 화면의 긴 도구 열과 불필요한 패널 | 도구를 가로 배치하고 탐험 중 에이전트 목록 숨김, 패널 높이 제한 | `src/style.css` |
| 작은 터치 타깃과 노치 주변 겹침 | 주요 모드/목록/닫기 버튼 확대, 안전영역 기준 상단 배치, 패널 내부 스크롤 | `src/style.css` |
| 저사양 터치 기기에도 높은 초기 품질이 선택됨 | 터치 우선 장치는 balanced, 4코어 이하 또는 2GB 이하로 보고된 장치는 performance 시작 | `src/performance.js` |
| 120ms보다 느린 프레임이 모두 제외되어 심한 지연을 감지하지 못함 | 최대 1초까지의 느린 프레임을 제한된 가중치로 반영, 긴 중단 구간만 제외 | `src/performance.js` |

일반 PC의 초기 품질 선택 기준과 수동 품질 지정은 유지한다. 터치 지원 노트북은 마우스와 터치 모두 사용할 수 있게 `any-pointer` 기준으로 조작부를 표시한다. 모바일 패널의 배경 블러를 제거해 화면 합성 비용을 줄였다.

## 검증 결과

- 자동 테스트 309개 통과. 새 입력/성능 테스트 13개 포함.
- 배포 전 검사, 정적 배포 산출물 검사, 변경 파일 공백 검사 통과.
- 공개 배포본 94개 파일, 3.57 MiB. 새 라이브러리/모델/텍스처 없음.
- Mac의 Codex 내장 브라우저에서 320x640, 390x844, 844x390, 768x1024, 1440x900 확인.
- 모바일 세로/가로 화면과 태블릿/PC 화면의 실제 스크린샷 확인. 확인한 화면에서 가로 넘침 없음.
- 320px 조작부: 스틱 오른쪽 118px, 동작 버튼 왼쪽 146px로 28px 간격 확보.
- 390px 상단 HUD/시계 사이 약 8px 간격 확인.
- 조이스틱 드래그 후 원위치 복귀, PC 드래그 후 입력 상태 0, 에이전트 카드 선택/닫기 확인.
- 멀티터치, 세 번째 손가락, 캡처 상실, 취소, 화면 회전, 숨김 상태는 자동 테스트로 검증. 실제 휴대폰에서 손가락으로 수행한 테스트는 아님.
- 실제 행성 QA `pass`; 모바일 및 가로 화면의 캔버스 다중 색상 픽셀 확인. 확인한 브라우저 콘솔 오류 없음.

## 실기기에서 남은 확인

1. iPhone Safari에서 세로/가로 전환, 홈 화면 복귀, 노치 영역, 두 손가락 확대 후 한 손가락 회전.
2. Android Chrome에서 이동 스틱을 누른 채 점프/승선 버튼 사용, 5분 산책 후 발열과 프레임 저하.
3. Windows Chrome/Edge/Firefox에서 마우스 휠과 트랙패드, 창 크기 변경, 한글 입력 상태의 F/ㄹ 승선, WebGL 복구.
4. 브라우저별 그래픽 드라이버 차이와 실제 저사양 기기의 FPS는 별도 측정. 반응형 화면 검사는 이 측정을 대신하지 않음.

입력 처리 근거: [MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events), [MDN any-pointer](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/any-pointer).
