## 유지한 항목

- 반지름 7.47, 집 6곳의 위치·소유자·크기.
- 배 크기 1.456과 사용자 지정 배 위치.
- 공용 공간 2곳과 게시판 1곳.
- 기본 포인트 오브젝트 25개, 저장 배치의 27개. 새 포인트 소품은 추가하지 않았다.
- Three.js, 구면 보행, 물 도보 진입 제한, 페이퍼컷 에셋.
- 넓은 외곽 땅을 소품으로 채우지 않았다. 별도 목적지가 없는 극지는 현재 여백으로 유지한다.

## 저장 배치 보호

- 새 저장 키는 `HandulPlanet_layout_harbor_v27`. 이전 v26 이하 키는 지우지 않는다.
- v26 배치는 이전 세대의 집 이동 마이그레이션을 반복하지 않고 구조 변경만 적용한다.
- 기본 집 위치와 기존 기본 마당이 일치하는 경우만 변경한다. 이동된 집이나 직접 그린 마당은 유지한다.
- 새 구역에 `id`, `districtId`를 부여하고 저장·불러오기·실행 취소에서 유지한다.
- 예: `core.promenade`, `jarvis.forecourt`, `anne.garden-coast`, `rose.quiet-garden`.
- 배를 기본 위치로 자동 복귀시키는 마이그레이션이나 호출 기능은 추가하지 않았다.

## 검증

### 기본 배치

- 자동 테스트 117개 통과.
- 전체 QA 통과.
- 집 6/6 진입 연결, 공용 공간 2/2 연결.
- 도로 9개, 표본 1,599개에서 장애물·수면 침범 0.
- 본토 도로 8개가 하나의 그래프로 연결. 등대 섬의 별도 길 1개 유지.
- 바다 42.6%, 육지 57.4%: 구면 4,096개 표본. 이전 42.9%와 큰 차이 없음.
- 해안 메시 경계와 물 판정 함수의 일치, 주기성, 변동 범위를 테스트.
- 주도로·골목 폭과 집 간격 유지.

### 항구 왕복

새 QA는 현재 배를 시작 전에 옮기지 않는다. 실제 이동 처리 함수와 물·장애물 판정을 사용하여 다음 단계를 순서대로 검사한다.

1. 시작점에서 부두까지 보행.
2. 현재 배가 실제 탑승 범위 안에 있는지 확인 후 승선.
3. 물 판정을 만족하는 경로를 찾아 등대 섬으로 운항.
4. 섬에 하선.
5. 같은 배에 재승선.
6. 원래 항구로 운항.
7. 항구에 하선.
8. 시작점까지 보행 복귀.

기본 배치에서 8단계 모두 통과했고 운항 경로는 33개 정점이었다. 테스트 후 배·플레이어·카메라 방향·점프 상태는 finally에서 원상 복구한다. 이는 런타임 시뮬레이션 검사이며, 사용자가 키를 누르는 전체 과정을 영상으로 기록한 검사는 아니다. F/ㄹ 입력은 별도의 기존 키보드 회귀 테스트로 확인한다.

### 저장 배치: 남은 확인 1건

저장된 27개 오브젝트와 여섯 집은 보존됐다. 집·공용 공간·도로·보행 검사는 통과했다.

**저장된 배가 기본 승선 부두에서 약 6.282 월드 단위 떨어져 있어, 부두에서 즉시 탑승하는 검사는 실패했다.** 원래 배 위치는 `[-0.7627984, -0.4034992, 0.5052989]` 방향이다. 이를 성공으로 숨기지 않도록 전체 QA에도 왕복 결과를 반영했다.

사용자에게 배 한 척만 부두 옆으로 옮겨도 되는지 확인을 요청했다. 승인 전에는 사용자 지정 배치를 변경하지 않는다. 이 확인이 끝나기 전에는 저장 배치의 항구 접근까지 마무리됐다고 판단하지 않는다.

### 화면 및 성능

- 1280×800 데스크톱과 390×844 모바일 뷰포트 확인.
- 정면 광장, Anne 정원, Ludwig·정자 구역의 카메라 구도 확인.
- 모바일 가로 넘침 없음. 캔버스 390×844, 표본 색상 31개로 비어 있지 않음.
- 기존 게시판 열기 정상.
- 모바일 뷰포트의 한 관측에서 약 59.9fps. 실제 휴대폰 성능 보장은 아니다.
- 그림자 광원을 추가하거나 물리 엔진을 교체하지 않았다.
